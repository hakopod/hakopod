# Mathesar automatic storage UI review

Independent review completed on 2026-10-05 using the
[dashboard checklist](ui-ux-checklist.md). The changed Mathesar storage flow is
approved for the tested presentation and interaction scope. No blocking visual
or interaction finding remains in that scope.

## Change and source coverage

The default **Media storage** choice is **Automatic local storage**. It requires
no storage-class name. **Existing shared storage** reveals a required **Shared
storage class** input. Switching back preserves the class draft while excluding
it from the automatic-storage request.

The former requirement to enter an RWX class before every Mathesar deployment
is historical. It applies only to the explicitly selected shared-storage mode.
The automatic choice creates an RWO media claim and places its consumers on one
node. The catalog and review explain that local disk is not replicated and
requires backups for node or disk loss.

Source inspection covered the Mathesar catalog metadata and blueprint,
`internal/spec/templates.go`, both template routes, `template-form.tsx`,
`template-requirements.ts`, the shared `SelectField`, form layout, help, error
and shell components. No dashboard application source needed changing.

## Findings resolved and limits

The source review found that catalog `notes` are not exposed by the template
API. The local-disk recovery limitation was moved into visible `requirements`,
so both the inspector and review display it.

Early capture attempts exposed harness synchronization mistakes: the URL
input's accessible name includes its help, a focus jump after review could
dismiss help during scrolling, and the script sent keyboard selection before
Radix transferred focus into the popup. The final harness uses the URL control,
natural initial help traversal plus explicit Enter activation, and observable
popup/focus/value waits. Each viewport/theme now reports failures independently;
failures are not skipped or converted to success.

Some full-page screenshots taken while scrolled include the normally offscreen
fixed skip link at the document scroll offset. Its source uses a negative
transform unless focused; the run independently confirms focus on the class
input/code. This full-page capture artifact is not evidence that the skip link
received focus. No screenshot-only product styling was added.

Canonical TOML equality and keyboard focus were checked for all 24 plan
reviews. This pass did not inspect every diff pagination page, operate a real
screen reader, test mobile software keyboards, or repeat the unrelated global
route matrix. It does not establish successful live provisioning, public
ingress, backup restoration or multi-node RWX operation. Runtime evidence and
its limits remain in the Mathesar blueprint acceptance record.

The final screenshots came from CI. The temporary local Vite/Chrome processes
and this review's local dependency/cache files were stopped or removed after
resource pressure prevented a reliable local run; source and evidence remain.
